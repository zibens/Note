# 并发 ：介绍

本章将介绍为单个运行进程提供的新抽象 ： 线程(thread)。 经典观点是一个程序只有一个执行点(一个PC)，但是多线程程序会有多个执行点(多个pc)。换一个角度来看，每个线程类似于独立的进程，只有一点区别 ： 它们共享地址空间，从而能够访问相同的数据。

因此，单个线程的状态与进程非常类似。线程之间的上下文切换类似于进程之间的上下文切换。 对于进程，将状态保存在PCB , 现在我们需要一个或多个TCB，保存每个线程的状态 ，主要区别 ：**线程的地址空间不变（不需要切换页表）**
	另一个区别在于栈

## 线程创建

在POSIX中，很简单

```c
#include <pthread.h>
int
pthread_create( pthread_t * thread,
			   const pthread_attr_t * attr,
			   void * (*start_routine)(void*)
               	void * arg;
)
```

该函数有4个参数 : thread attr  start_routine arg
第一个参数是指向 pthread_t结构类型的指针 ， 我们将利用这个结构与该线程交互
第二个用于指定该线程可能具有的任何属性。默认NULL
第三个最复杂，但他实际上只是问 ： 这个线程应该在哪个函数中运行？在C中，我们把它称为一个函数指针，这个指针告诉我们 ： 一个函数名称 ，它被传入一个类型为*void的参数 ，并且返回一个*void类型参数
第四个就是要传递给线程开始执行的函数的参数。

```c
typedef struct myarg_t{
    int a;
    int b;
}myarg_t;

void *mythread(void * arg){
    myarg_t *m = (myarg_t *)arg;
    printf("%d %d\n" , m->a , m->b);
    return NULL;
}

int main(){
    pthread_t p;
    int rc;
    marg_t args;
    args.a = 10;
    args.b  = 20;
    rc = pthread_create(&p , NULL ,mythread , &args);
}
```

这时候只是创建了，不会执行这个函数

## 锁

锁来提供互斥进入临界区的函数。

```c
int pthread_mutex_lock (pthread_mutex_t * mutex);
int pthread_mutex_unlock(pthread_mutex_t *mutex);
```

**互斥 ： 保证同一时间内，只有一个线程可以进入临界区，从而避免出现竞态条件，使程序产生确定性（determinate）的输出。** 
使用锁的时候要初始化， 所有锁必须正确初始化，以确保它们具有正确的值，并在锁和解锁被调用时按照需要工作
在POSIX线程，有两种方法初始化锁。一种方法是使用 **PTHREAD_MUTEX_INITALIZER**

```C
pthread_mutext_t lock = PTHREAD_MUTEX_INITIALIZER;
```

这样做会将锁设置为默认值，从而使锁可用。舒适化的动态方法是调用函数

```c
int rc = pthread_mutex_init(&lock , NULL);
assert(rc == 0);
```

此函数的第一个参数是锁本身的地址，而第二个参数是一组可选属性。

# 锁

并发编程的一个最基本的问题： **我们希望原子式执行一系列指令，但由于单处理器上的中断(或者多个线程在多处理器上并发执行)，我们无法做到** 程序员在代码中加锁，放在临界区周围，保证临界区能够像单条原子指令一样执行

## 锁的基本思想

锁就是一个变量，这个变量保存了锁在某一时刻的状态 ， 要么是可用的 ， 要么是被占用的

## Pthread锁

POSIX库将锁称为互斥量 ， 因为它被用来提供线程之间的互斥。

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
Pthread_mutex_lock(&lock);
b = b + 1;
Pthread_mutex_unlock(&lock);
```

POSIX的lock和unlock函数会传入一个变量，因为我们可能用不同的锁来保护不同的变量。这样可以增加并发 ： 不同于临界区都是用同一个大锁(粗粒度的锁策略) ， 使用不同的锁保护不同的数据结构，更多线程进入临界区（细粒度）

## 实现一个锁

我们需要硬件和操作系统的帮助来实现一个可用的锁。 首先来看锁的标准

- 锁是否能完成它的基本任务 ：提供互斥
- 公平性。当锁可用时，是否每一个竞争线程有公平的机会抢到锁
- 性能。

### 控制中断

最早提供互斥的方案，就是在临界区关闭中断。这个解决方案为单处理器系统开发

```c
void lock(){
    DisableInterrupts();
}
void unlock(){
    EnalbeInterrupts();
}
```

有很多缺点

### 自旋锁

```c
void lock(lock_t * mutex){
    while(mutex->flag == 1);
    mutex->flag = 1;
}
```

然而这段代码无法实现互斥 ：原因是缺乏 **原子性** 和 **内存屏障**，导致多个线程可能在同一时间获取锁。
**如何实现可用的自旋锁？**
一些系统提供了硬件指令在x86上，是xchg（原子交换）指令

```c
int TestAndSet(int *old_ptr , int new){
    int old = *old_ptr;
    *old_ptr = new;
    return old;
}
//TestAndSet 的原子性来自于操作系统提供的底层硬件支持或者处理器指令集
void lock(lock_t * lock){
    while(TestAndSet(&lock->flag) == 1);
    mutex->flag = 1;
}
```

### 评价自旋锁

有正确性
没有公平性 ， 实际上自旋的线程在竞争条件下可能会永远自选。可能会导致饿死
性能： 在单CPU性能开销大 ， 多CPU性能效果不错

### 自旋转过多怎么办

以两个线程运行在单处理器上为例 ， 当一个线程（线程0）持有锁时，被中断。第二个线程（线程1）去获取锁，发现锁已经被持有。因此，他就开始自旋。接着自旋。

然后它继续自旋，最后时钟中断，线程0重新运行，它释放锁。最后，1不需要继续自旋了，它获取了锁。此时，浪费掉了一整个时间片，如果有N 个线程去竞争一个锁，会浪费N-1时间片 ， 那么**如何让锁不会不必要的自旋**

有一种简单的方法就是，当要自旋的时候，放弃CPU

```c
void lock(){
    while(TestAndSet(&lock , 1) == 1)yield;
}
```

我们假定操作系统提供原语yield， 这个系统调用能够使得running->ready ， 因此让出线程本质上取消调度了他自己

但是上下文切换的成本大，而且我们还没有考虑饿死的情况，显然需要另外一种方法

**使用队列 ： 休眠替代自旋**
我们显示的施加某种控制，决定锁释放时，谁能抢到锁。 `park()`能够让调用线程休眠 `unpark()`唤醒threadID标识的线程。调用者在获取不到锁时睡眠，锁可用时唤醒

```c
typedef struct lock_t{
    int flag;
    int guard;
    queue_t *q;
}lock_t;

void lock_init(lock_t *m){
    m->flag = 0;
    m->guard =0;
    queue_init(m->q);
}

void lock(lock_t *m){
    while(TestAndSet(&m->guard, 1) == 1); //acquire guard lock by spinning
    if(m->flag == 0){
        m->flag =1; //lock is acquired
        m->guard = 0;
    }
    else{
        queue_add(m->q , gettid());
        m->guard = 0;
        park();
    }
}

void unlock(lock_t *m){
    while(TestAndSet(&m->guard ,1) == 1); 
    if(queue_empty(m->q))m->flag = 0;
    else unpark(queue_remove(m->q));
    m->guard = 0;
}
```

```c
#include <stdio.h>
#include "pthread.h"

int bcouldprint = 0;
int bisDone = 0;

pthread_cond_t cond_b;
pthread_mutex_t lock;
pthread_cond_t cond_c;

void init(){
    pthread_cond_init(&cond_b , NULL);
    pthread_cond_init(&cond_c , NULL);
    pthread_mutex_init(&lock , NULL);
}

void *f1(void * arg){
    pthread_mutex_lock(&lock);
    while(bcouldprint == 0){
        pthread_cond_wait(&cond_b , &lock);
    };
    printf("B\n");
    bisDone = 1;
    pthread_cond_signal(&cond_c);
    pthread_mutex_unlock(&lock);
    return NULL;
}
void *f2(void * arg){
    printf("A\n");
    pthread_mutex_lock(&lock);
    bcouldprint = 1;
    pthread_cond_signal(&cond_b);
    while(bisDone == 0){
        pthread_cond_wait(&cond_c , &lock);
    };
    printf("C\n");
    pthread_mutex_unlock(&lock);
    return NULL;
}

int main(){
    init();
    pthread_t pthread1;
    pthread_t pthread2;
    pthread_create(&pthread1 , NULL , f1 , NULL);
    pthread_create(&pthread2 , NULL , f2 , NULL);
    pthread_join(pthread1 , NULL);
    pthread_join(pthread2 , NULL);
}
```
