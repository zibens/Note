## 虚拟化内存

现代机器提供的物理内存模型非常简单。内存就是一个字节数组。

```c
int main(int argc,char *argv[]){
    int *p = (int*)malloc(sizeof(int));
    assert(p != NULL);
    printf("(%d) memory address of p:%08x\n",getpid(),(unsigned long)p);
    *p = 0;
    while (1)
    {
        sleep(1);
        *p = *p + 1;
        printf("(%d) p: %d\n",getpid(),*p);
    }
    return 0;
}
```

会发现，每个程序都在相同的地址处分配了内存，但每个似乎都独立更新了这里的值！就好像每个正在运行的程序都有自己私有内存，而不是与其他正在运行的程序共享相同的物理内存

**实际上，这正是操作系统虚拟化内存时发生的情况** 每个进程访问自己的私有虚拟地址空间，操作系统以某种方式映射到机器的物理内存上。一个正在运行的程序中的内存引用不会影响其他进程的地址空间。 对于正在运行的程序，它完全拥有自己的物理内存。但实际情况是，**物理内存是由操作系统管理的共享资源** 

## 并发

```c
#include<pthread.h>
#include<stdio.h>
#include<stdlib.h>
volatile int counter = 0;
int loops;
void *worker(void * arg){
    int i;
    for(int i = 0;i < loops;i++){
        counter++;
    }
    return NULL;
}
int main(int argc,char *argv[]){
    if(argc != 2){
        fprintf(stderr,"usage:threads<value>\n");
        exit(1);
    }
    loops = atoi(argv[1]);
    pthread_t p1,p2;
    int ret = pthread_create(&p1,NULL,worker,NULL);
    if(ret == -1){
        perror("pthread_create");
        exit(1);
    }
    ret = pthread_create(&p2,NULL,worker,NULL);
    if(ret == -1){
        perror("pthread_create");
        exit(1);
    }
    pthread_join(p1,NULL);
    pthread_join(p2,NULL);
    printf("Final Value     : %d\n",counter);
    return 0;
}

```

这段代码中，当我们把loops设置为1000 ，最终答案是2000.
但是10000的时候， 就不是20000 ， 而是13666 ， 或其他数字

事实证明，这些奇怪的结果与指令如何执行有关，指令每次执行一条。 上面程序关键的地方是增加共享计数器的地方 ， **它需要3条指令，一条将计数器的值从内存加载到寄存器 ， 一条将其递增 ， 一条将其保存返回内存**。 因为这三条指令并不是以原子方式执行的，所以奇怪的事会发生。

## 持久性

操作系统中管理磁盘的软件称为**文件系统** 。 因此它负责以可靠和高效的方式，将用户创建的任何文件存储在系统的磁盘上。

不像操作系统为cpu和内存提供的抽象 ，os不会为每个应用程序创建专用的虚拟磁盘。相反，它假设用户经常需要共享文件中的信息。

对于操作系统为了实际写入磁盘 ， 文件系统做了很多工作 ，但幸运的是操作系统提供了一种通过系统调用来访问设备的标准和简单的方法。 **因此，os有时被视为标准库**
为了处理写入期间系统崩溃的问题，大多数文件系统都包含某种复杂的写入协议

# 抽象：进程

操作系统通过虚拟化cpu来提供这种抽象。 通过让一个进程只运行一个时间片，然后切换到其他进程，操作系统提供了存在多个虚拟cpu的假象。 这就是**时分共享（time sharing）**cpu技术。开销就是性能损失，因为如果cpu必须共享，每个进程的运行就会慢一些。 

## 抽象：进程

操作系统为正在运行的程序提供的抽象，就是所谓的进程。

进程的机器状态：程序在运行时可以读取或更新的内容。
进程的机器状态有一个明显的组成部分，就是它的内存。指进程可以访问的内存(称为**地址空间**)是该进程的一部分
进程的机器状态的另一部分是**寄存器**

## 进程API

所有现代os都以某种形式提供这些API

- **创建** os必须包含一些创建新进程的方法
- **销毁** 
- **等待** 有时等待进程停止运行是有用的，因此经常提供某种等待接口
- **其他控制** 例如：大多os提供某种方法来暂停进程，然后恢复
- **状态** 通常也有一些接口可以获得有关进程的状态信息

## 进程创建：更多细节

操作系统运行程序的**第一件事是将代码和所有静态数据加载到内存中，加载到进程的地址空间中**。程序最初以某种可执行格式驻留在磁盘上。 因此，将程序和静态数据加载到内存的过程中，需要操作系统从磁盘中读这些字节，并将它们放在内存中的某处。

将代码和静态数据加载到内存后，操作系统还必须为程序的运行时栈分配一些内存（C程序使用栈存放局部变量，函数参数和返回地址）。操作系统分配这些内存，并提供给进程。操作系统也可能会用参数初始化栈。 具体来说，他会将参数填入main函数，即argc,argv

操作系统也可能为程序的堆分配一些内存。操作系统还将执行一些其他初始化任务，**特别是与I/O相关的任务**

通过将代码和静态数据加载到内存中，通过创建和初始化栈以及执行与I/O设置相关的其他工作，OS现在终于为程序执行搭好了舞台。然后他有最后一项任务：启动程序，在入口处运行，即main()。os将cpu的控制权转移到新创建的进程中，从而开始执行。

## 进程状态

- **运行** ： 在运行状态下，进程正在处理器上运行。这意味着它正在执行指令
- **就绪** ： 在就绪状态下，进程已准备好运行，但由于某种原因，os选择不在此时运行
- **阻塞** ： 在阻塞下，一个进程执行了某种操作，直到发生其他事件时才会准备运行。

os是一个程序，和其他进程一样，它有一些关键的数据结构来跟踪各种相关的信息。

# 插叙：进程API

## fork()系统调用

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int 
main(int argc , char * argv[]){
    printf("hello world (pid:%d)\n" , (int)getpid());

    int rc = fork();
    if(rc < 0){
        fprintf(2 , "fork failed\n");
        exit(1);
    }
    else if(rc == 0){
        printf("hello , I am child (pid:%d)\n" , (int)getpid());
    }
    else{
        printf("hello , I am parent of %d (pid:%d)\n" , rc , (int)getpid());
    }
    return 0;
}
```

```
hello world (pid:2003)
hello , I am child (pid:2008)
hello , I am parent of 2008 (pid:2003)
```

**子进程并不是完全拷贝了父进程**

## wait()系统调用

有时候父进程需要等待子进程执行完毕 ， 这很有用。

```c
int 
main(int argc , char * argv[]){
    printf("hello world (pid:%d)\n" , (int)getpid());

    int rc = fork();
    if(rc < 0){
        fprintf(2 , "fork failed\n");
        exit(1);
    }
    else if(rc == 0){
        printf("hello , I am child (pid:%d)\n" , (int)getpid());
    }
    else{
        int wc = wait();
        printf("hello , I am parent of %d (pid:%d)\n" , rc , (int)getpid());
    }
    return 0;
}
```

在这个例子中，父进程调用`wait()` ,延迟自己的执行，直到子进程执行完毕。当子进程结束时，`wait()`才返回父进程。

## exec()

这个系统调用可以让子进程执行与父进程不同的程序。

```c
int 
main(int argc , char * argv[]){
    printf("hello world (pid:%d)\n" , (int)getpid());

    int rc = fork();
    if(rc < 0){
        fprintf(2 , "fork failed\n");
        exit(1);
    }
    else if(rc == 0){
        printf("hello , I am child (pid:%d)\n" , (int)getpid());
         char *myargs[3];
         myargs[0] = strdup("wc");
         myargs[1] = strdup("p3.c");
         myargs[2] = NULL;
         execvp(myargs[0] , myargs);
         printf("this shouldn't print out");
    }
    else{
        int wc = wait();
        printf("hello , I am parent of %d (pid:%d)\n" , rc , (int)getpid());
    }
    return 0;
}
```

这个例子中， 子进程调用`execvp()`来运行字符计数程序wc。

exec ， 给定可执行程序的名称(如wc)以及需要的参数(如p3.c)后，exec会从可执行程序中加载代码和静态数据，并用它覆写自己的代码段，堆栈及其他空间也会被重新初始化。然后os执行该程序，将参数通过argv传递给该进程。

## 为什么这样设计API

事实证明，这种分离fork()和exec()的做法在构建UNIX shell的时候非常有用，因为这给了shell在fork之后exec之前运行代码的机会 ，这些代码可以在运行新程序前改变环境。 



# 机制：受限直接执行

操作系统以**时分共享**CPU，就实现了虚拟化

## 基本技巧：受限直接执行

为了使程序尽可能块地运行，操作系统开发人员想出来一种计数——我们称之位首先的直接执行。
因此，当OS希望启动程序运行时，它会在进程列表中为其创建一个进行条目，为其分配一些内存，将程序代码（从磁盘）加载到内存中，找到入口点，跳转到那里，并开始运行用户的代码

这时有两个问题：

- 如果我们只运行一个程序，os怎么能确保程序不做任何我们不希望它做的事，同时并高效地运行
- os如何让进程停下来切换另一个进行，从而实现虚拟化CPU

## 问题1：受限制的操作

程序在CPU上运行，会带来一个问题——如果进程希望执行某种受限操作（如向磁盘发出I/O请求或获得更多系统资源），该怎么办？

我们采用的方法是 引入用户模式 ， 在用户模式下运行的代码会受到限制。
内核模式 ， 操作系统（内核）就以这个模式运行，可以执行特权指令

要执行系统调用，程序必须执行特殊的 `trap` 指令。 该指令同时跳入内核并将特权级别提升到内核模式。 进入内核后，系统就可以执行任何需要的特权操作。 完成后，os调用一个特殊的从陷阱返回(return-from-trap)指令，回到用户模式。

trap时，硬件需要小心，因为它必须确保存储足够的**调用者寄存器**，以便在os发出从trap返回时，能够正确返回。

内核在通过在启动时设置陷阱表（trap table）来实现。当机器启动时，它在内核态，os做的第一件事就是高速硬件在发生某些trap时要执行哪些代码

## 问题2：在进程中切换

当进程在CPU上运行时，这时候，操作系统没有在CPU上运行，于是有个关键问题：**操作系统如何重新获得CPU的控制权，以便它可以在进行之间切换？**

> 协作方式 ： 等待系统调用

在这种风格下，os相信系统的进程会合理运行。运行时间过长的进程被假定会放弃CPU。

但这种方式有些被动了，例如：某个进程进入无线循环，那么os能做什么？

> 非协作方式：操作系统进行控制



事实证明，如果没有硬件额外帮助，如果进程拒绝进行系统调用，从而将控制权交还给os，那么os无法做任何事情。

那么人们发现了 ：**时钟中断**

> 保存和恢复上下文

如果决定切换,那么os就会执行一些底层代码,也就是**上下文切换**. os要做的就是为当前正在运行的进程保存一些寄存器的值 (到它的内核栈), 并为即将执行的进程恢复一些寄存器的值(从它的内核栈)

## 担心并发吗?

操作系统可能简单的决定 ,在中断处理期间禁止中断. 这样做可以确保在处理一个中断时,不会将其他中断交给CPU.还有很多锁技术.

## 小结

受限直接运行基本思路很简单: 就让你想运行的程序在CPU上运行,但首先确保设置好硬件,以便在没有os帮助的情况下限制进程可以执行的操作.
